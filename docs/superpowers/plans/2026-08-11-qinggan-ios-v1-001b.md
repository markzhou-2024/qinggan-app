# QingGan Native Foundation & Real Itinerary Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the minimal real Day1-Day10 itinerary API and a testable Native Today→recommended-navigation foundation that can use fixtures during development and the real API at acceptance.

**Architecture:** Spring Boot exposes one versioned itinerary document backed by Flyway seed data. `QingGanCore` is a pure Swift Package containing domain use cases and repository contracts; infrastructure implements HTTP/cache/navigation behind those contracts; SwiftUI Today consumes only a view model. The fixture repository makes the native path runnable while the remote backend is developed in parallel.

**Tech Stack:** Java 17, Spring Boot 3.5.7, JPA, Flyway, H2 test runtime/MySQL production, JUnit; Swift 6.3, Swift Package Manager, Foundation, URLSession, XCTest, SwiftUI, CoreLocation, MapKit; Xcode 26.6.

## Global Constraints

- Native iOS is the primary client; do not create a WebView, React Native, Flutter, Capacitor, or Cordova client.
- Keep the backend small: implement only `GET /api/v1/trips/{tripId}/itinerary` plus data needed by the Native vertical slice.
- Backend seed uses the canonical real Day1-Day10 QingGan route; unverified POIs use `verificationStatus = PENDING` and no invented precise coordinate.
- `GeoCoordinate` always carries its `CoordinateSystem`; GCJ02 must never be used as WGS84.
- Views do not issue HTTP requests, access cache, or construct navigation URLs.
- `TripDay` and `TripStop` preserve sequence, planned/current/completed/skipped states and planned-distance/drive data for future journey and driving progress.
- Today is composed from `DayHeaderSection`, `JourneyProgressSection`, `NextStopSection`, `DrivingStatusSection`, `WeatherSection`, `TonightSection`, and `DailyMomentSection`; unimplemented sections render nothing rather than turning TodayView into a monolith.
- Future weather advice, daily challenge, badges, DaySummary, TripMemory, PhotoReference, and final-report logic belong to separate domain/feature modules; do not implement their engines in this task.
- Quick roadside actions must extend `NavigationService`/`ExternalMapService`; no SwiftUI View may construct a map URL. For the family Tesla Model Y standard-range vehicle, the future action is `charging`, not fuel; charging-station search, state-of-charge, and EV route planning remain outside this task.
- Use fixtures for native development but do not report the vertical slice complete until it runs against the real API.
- Trip ID is non-secret configuration; trip token is never committed and is stored only through `TripCredentialStore`/Keychain.
- No login, user system, family location sharing, background tracking, weather redesign, full Trip/Map/Memories features, or custom route engine.
- Commit each independently verified stage.
