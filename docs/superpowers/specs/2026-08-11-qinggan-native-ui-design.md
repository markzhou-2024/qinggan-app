# 青甘随行原生 SwiftUI UI V1 设计说明

**状态：** 待用户复核  
**日期：** 2026-08-11  
**视觉依据：** `UI/UI.png` 与《青甘大环线自驾助手 V1 UI 页面设计说明》

## 1. 目标与范围

将现有原生 iOS 应用由单页行程信息升级为家庭自驾旅途中可执行的五栏助手。用户每天打开应用后，能看见当天的路线、进度、下一导航点和住宿，并能按顺序处理当天任务、打开预设导航、记录旅途及查看十天全局进度。

本增量包含：

- 五个底部标签页：今日、地图、打卡、行程、我的；
- 今日页、今日清单、路线导航、旅途打卡、十天总览的设计稿对应界面；
- 本地、内存态的完成与跳过操作，以及同步的今日和全程进度；
- 对现有 `Trip`、`TripDay`、`TripStop`、`Stay` 与 `NavigationPoint` 的只读适配；
- 高德深链的既有导航能力；无法开启高德时保留系统地图备用入口；
- 明确的未开始、进行中、已完成与离线数据状态。

本增量不包含：真实地图 SDK、实时天气、照片写入系统相册、云端同步、登录、推送、行程编辑、景点图片下载或路线实时规划。地图页先以可访问的路线节点列表呈现，不伪造地图瓦片或实时路况。

## 2. 视觉与可访问性原则

沿用设计稿的湖蓝、翡翠青和沙漠暖金：青色作为行动及完成态，暖金只用于天气或提示，系统主文本使用深海军蓝。页面保持白底、圆角卡片和 12–16pt 间距，避免将关键信息只放在照片上。

- 所有可点击控件最小尺寸为 44×44pt；
- 完成、待办、跳过及当前天同时使用图标、文字和颜色；
- 正文使用 Dynamic Type 友好的 SwiftUI 字体，辅助文字不会低于可读的默认小字号；
- 进度条、Tab 与图片缩略图提供 VoiceOver 标签；
- 图片缺失时使用系统图标和渐变背景，不把 ASCII、表情或手工绘制图形作为资源替代品；
- 设计稿中的旅行摄影先不加入产品界面，待提供合法可复用素材后以真实资源接入。

## 3. 信息架构和核心流程

应用根视图使用 `TabView`，默认选择“今日”。今日页内的“查看清单”通过 sheet 或导航栈进入今日清单；“一键导航”和地图页底部主按钮始终调用当前下一未完成且未跳过节点的推荐导航点。

```text
今日 ── 查看清单 ──> 今日清单 ── 完成/跳过 ──> 今日进度 + 下一站更新
 │                        │
 ├─ 一键导航 ──────────────┴─> 高德/系统地图
 └─ 地图 ────────────────> 路线节点与下一站导航

打卡 ──> 今日照片/感受的本地 UI 状态
行程 ──> Day 1–Day 10 总览及当前日
我的 ──> V1 账户占位与数据来源说明
```

### 3.1 今日

显示 Day 徽标、日期、出发地至目的地、当天标题、里程、驾驶时长、完成数量、进度条、四个快捷入口、下一站和今晚住宿。数据均来自 `TodaySnapshot` 和当前 `TripDay`；若无数据，保留清晰的空状态，而不是编造天气、距离或图片。

### 3.2 今日清单

按“出发准备、沿途必经、补能、用餐与休息、住宿、旅途记录”分组。现有领域模型只含停靠点：它们直接映射为沿途、补能、用餐与住宿；出发准备与旅途记录作为不可改变领域数据的 UI 提醒项。停止项可完成；`isOptional == true` 的停止项另可跳过。完成或跳过后，列表、首页、地图和总览即时刷新。

### 3.3 地图

不引入地图 SDK。使用路线垂直轨迹、节点类型图标和状态，表达起点、景点、补能、用餐与住宿的顺序；底部卡固定显示下一站与导航按钮。点击节点可展开名称、备注、核验状态与导航操作。高德不可用时使用现有 Apple Maps 备用链接。

### 3.4 打卡

显示“立即打卡”主按钮、筛选项及当天时间线。V1 的打卡不申请照片权限：按钮切换当前日的本地“已记录”状态并记录时间；照片格使用系统相册图标的空状态。该行为在应用进程存续期间可见，不宣称已保存到相册或云端。

### 3.5 十天总览

展示完成天数、总体百分比及 Day 1–10。当前天以边框和“进行中”标签突出；当日所有可执行停止项完成或跳过后标为“已完成”；未来天为“待开始”。点击某天切换行程页的选中项，不修改当前日期，也不伪造跨日执行。

### 3.6 我的

保留第五 Tab，显示“青甘随行”、当前数据来源、版本与隐私提示。它不是设计稿中未定义的新功能入口，也不实现账户体系。

## 4. 状态与数据边界

现有核心模型中的 `TripStop.status` 为不可变字段，仓库当前是读取行程。因此 UI 增量引入应用层 `TripPresentationStore`：加载一次 `Trip`，在内存中持有按 stop ID 覆盖的 `StopStatus`，并导出用于各页的派生状态。

- `planned` / `arrived`：待办；
- `completed`：已完成；
- `skipped`：已跳过；
- `moved`：以“已调整”文字显示且不被当作下一站；
- 下一站继续使用原有排序规则，排除起点、完成和跳过项；
- 写入行为仅发生在 presentation store；不修改 fixture、Core 的解码约定或后端 API；
- `TodayViewModel` 继续负责加载和旅行阶段计算，UI store 负责显示状态与交互。

`preTrip`、`postTrip`、加载失败和无当天行程均保留已有专用页面。就绪状态才展示底部导航及今日执行界面。

## 5. 组件边界

- `QingGanApp`: 创建仓库、`TodayViewModel` 和共享 presentation store。
- `TodayView`: 仅决定旅行阶段与根导航，拆出就绪态 Tab shell。
- `TripPresentationStore`: 当前行程、覆盖状态、派生今日进度、下一站、日完成度和打卡状态。
- `TodayDashboardView`: 今日卡片、快捷入口、下一站、住宿。
- `TodayChecklistView`: 分组清单及完成/跳过操作。
- `RouteNavigationView`: 路线节点和导航操作。
- `JourneyCheckInView`: 打卡视觉状态和本地记录。
- `TenDayOverviewView`: 全局进度和日期列表。
- `ProfileView`: V1 信息页。
- 小型私有视图负责进度条、状态徽标、卡片与格式化，避免把全部布局放回单一文件。

## 6. 测试与验收

先在 `QingGanCoreTests` 为用于 UI 的纯派生逻辑写测试，并在失败后实现。至少覆盖：

1. 停止项完成后，今日进度与下一站更新；
2. 可选停止项可跳过，跳过项不再成为下一站；
3. 非可选停止项不会出现跳过动作；
4. 当天所有执行节点解决后，十天总览将该天标记为已完成；
5. 完成数量分母不含起点，分子不把跳过算作完成；
6. 旅行前、旅行中、旅行后仍显示正确根状态；
7. 高德优先、Apple Maps 备用的既有导航服务回归通过。

构建验收为 `swift test --package-path ios/QingGanCore` 和 `xcodebuild` 的 iOS Simulator 构建。界面验收使用 iPhone 16 尺寸，人工核查：无裁切、无重叠、44pt 点击区、中文长文案、深浅状态及动态文字放大。

## 7. 设计审计结论如何落实

- 照片文本对比度风险：核心文字均放在不透明或高对比背景卡；
- 小点击区风险：圆形状态按钮、Tab 和快捷卡都以 44pt 命中区实现；
- 仅颜色传达状态风险：每种状态都有图标和中文状态词；
- 真实地图不确定性：路线页提供节点序列及可用导航深链，不宣称实时地图；
- 旅行记录权限风险：V1 不申请照片权限，也不把本地视觉状态描述为相册保存。
